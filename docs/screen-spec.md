# 画面仕様

- 状態: フェーズ3 の画面をすべて記載（2026-10-04）
- 関連: [設計概要](design-overview.md)（アカウントと権限、セッション）

## 1. 共通

### 1.1 レイアウト

- 上部のナビゲーションに、ダッシュボード、加入者、AVクライアント、サーバー証明書、ログ、監査ログ（管理者のみ）、アカウント（管理者のみ）と、ログイン中のユーザーID のメニューを出す。画面幅が狭いときは項目の並びを複数行に回す。
- パスワードの変更待ちの間は、ユーザーID のメニュー以外を出さない。
- ユーザーID のメニューには、アカウントの種類、パスワード変更（最初の管理者以外）、ログアウトを出す。
- 下部に BFF のバージョンを出す。
- 日時は BFF のタイムゾーン（`TZ`）で `2006-01-02 15:04:05 JST` の形で出す。

### 1.2 ログインと権限

| 状態 | 通常の画面遷移 | htmx の操作 |
|---|---|---|
| 未ログイン、セッション切れ | ログイン画面へ移動する（303）。元のパスを `next` に入れる | 401 と `HX-Redirect` でログイン画面へ移動する |
| パスワードの変更待ち | パスワード変更画面へ移動する | 403 と `HX-Redirect` でパスワード変更画面へ移動する |
| 権限のない画面・操作 | 403 のエラー画面 | 403 のエラー画面 |

- ログイン後の移動先（`next`）は、同じサイトの絶対パスだけを使う。それ以外は `/` にする。
- 別のサイトからのフォーム送信は 403 で拒否する（`CrossOriginProtection`）。

### 1.3 操作の結果

- 変更の操作は htmx で送り、画面の該当部分（`#accounts`、`#subscriber`、`#avclients`、`#avclient`、`#servercert`）だけを差し替える。結果は部分の先頭に出す。
- 削除の後は一覧の画面へ移動し、削除したことを出す。
- 削除はブラウザの確認ダイアログを出してから行う。
- 入力の誤りでフォームを出し直すときは、パスワード以外の入力を残す。
- 入力の誤りなどは 4xx、処理の失敗は 5xx で、説明つきの HTML を返す。htmx は既定では 4xx / 5xx の応答を差し替えないので、`htmx-config` の `responseHandling` で差し替えるようにしている。
- htmx の操作で権限エラーなどのエラー画面を返すときは、本文（`main`）全体をエラーの表示に置き換える（`HX-Retarget` / `HX-Reswap`）。

## 2. ログイン（`/login`）

- 誰でも開ける。ログイン済みなら `next`（なければ `/`）へ移動する。
- 入力: ユーザーID、パスワード。

| 結果 | 表示 |
|---|---|
| 成功 | `next` へ移動する。パスワードの変更待ちなら、パスワード変更画面へ移動する |
| ユーザーID かパスワードが違う（存在しない ID を含む） | 401「ユーザーID またはパスワードが違います。」 |
| 失敗が続いてロック中 | 429「ログインの失敗が続いたため、このユーザーID では一時的にログインできません。…」 |

- ログアウトはメニューのボタン（`POST /logout`）で行い、ログイン画面へ移動する。

## 3. パスワード変更（`/password`）

- 管理者と一般ユーザーが使える。最初の管理者には 403 で「`.env` で変更してください」と出す。
- 入力: 現在のパスワード、新しいパスワード、新しいパスワード（確認）。
- 他人が設定したパスワードでログインしている間は、「続けるには、パスワードを変更してください。」と出し、この画面以外を使わせない。
- 成功したら `/password?done=1` へ移動して完了を出す。他の端末のセッションは無効になる。

| 誤り | 表示 |
|---|---|
| 確認用と一致しない | 「新しいパスワードと確認用のパスワードが一致しません。」 |
| 現在のパスワードが違う | 「現在のパスワードが違います。」 |
| 規則に合わない | 「パスワードは 8 文字以上にしてください。」など |
| 現在と同じ | 「現在と同じパスワードは使えません。」 |

## 4. アカウント管理（`/accounts`）

- 管理者（最初の管理者を含む）だけが使える。

### 4.1 一覧

| 項目 | 内容 |
|---|---|
| ユーザーID | |
| 種類 | 最初の管理者 / 管理者 / 一般ユーザー |
| 作成 | 作成日時と作成者。最初の管理者は「.env」 |
| 状態 | パスワードの変更待ちなら「パスワード変更待ち」 |
| 操作 | 操作できるアカウントにだけ出す。パスワードの再設定（新しいパスワードと確認）と削除 |

- 最初の管理者を先頭に、残りはユーザーID の順に並べる。
- 操作できるのは、最初の管理者なら管理者と一般ユーザー、管理者なら一般ユーザー。

### 4.2 作成

- 入力: ユーザーID、種類（作成できる種類だけを選択肢に出す）、初期パスワード、初期パスワード（確認）。
- 作成したアカウントは、最初のログインでパスワードの変更を求める。

| 誤り | 表示 |
|---|---|
| ユーザーID の形式 | 「ユーザーID は 1〜64 文字の英数字と . _ @ - で指定してください。」 |
| 既にある（最初の管理者の ID を含む） | 409「そのユーザーID は既に使われています。」 |
| 確認用と一致しない、規則に合わない | パスワード変更と同じ |
| 権限がない種類 | 403「この操作の権限がありません。」 |

## 5. ダッシュボード（`/`）

- ログインしたユーザーなら誰でも開ける。
- 管理API から取得した加入者数、AVクライアント数、aka-only-server のバージョン、起動日時、AV用サーバー証明書の有効期限、認証ベクターAPI の平文HTTP の有効・無効を出す。
- 証明書が期限切れか 30 日以内に切れる AVクライアントがあれば、警告を出す。AV用サーバー証明書の期限も同じように目立たせる。
- 直近のログ（10 件、新しい順）を出す。
- 管理API に接続できないときは、原因の見当（設計概要 7 章）を出す。

## 6. 加入者

### 6.1 一覧（`/subscribers`）

- 全員が使える。IMSI の辞書順に 50 件ずつ出す。「次のページ」「先頭へ」で移動する。
- IMSI の前方一致（15 桁までの数字）で絞り込める。件数（総数または一致数）を出す。
- 項目: IMSI、SQN、AMF、SQN 増加タイプ、平文HTTP、許可クライアント（名前）、更新日時。

### 6.2 登録（`/subscribers/new`）

- 全員が使える。
- 入力: IMSI、Ki、OPc、SQN（既定 `000000000000`）、AMF（既定 `8000`）、SQN 増加タイプ（既定 inc32）、許可クライアント（登録済みの AVクライアントから選ぶ）、平文HTTP の許可。
- 形式の誤りは項目ごとに示し、入力（Ki / OPc を含む）を残す。登録が終わった後は、一般ユーザーには Ki / OPc を出さない。
- 成功したら詳細へ移動して「加入者を登録しました。」と出す。同じ IMSI があれば 409「その IMSI の加入者は既に登録されています。」。

### 6.3 詳細（`/subscribers/{imsi}`）

| 部分 | 一般ユーザー | 管理者 |
|---|---|---|
| SQN、AMF、SQN 増加タイプ、登録・更新日時 | ○ | ○ |
| 許可クライアントと平文HTTP の変更 | ○ | ○ |
| Ki / OPc の表示（ボタンを押したときだけ取得。aka-only-server の監査ログに残る） | × | ○ |
| 認証パラメーターの変更（Ki、OPc、SQN、AMF、SQN 増加タイプ） | × | ○ |
| 削除（確認ダイアログを出す） | ○ | ○ |

- 認証パラメーターの変更は、入力のあった Ki / OPc と、値が変わった SQN / AMF / SQN 増加タイプだけを送る。何も変わっていなければ「変更はありません。」と出す。
- 表示した Ki / OPc は、ほかの操作をしたり画面を移動したりすると消える。

## 7. AVクライアント

### 7.1 一覧と登録（`/av-clients`）

- 一覧は全員が見られる（加入者の許可クライアントを選ぶため）。項目: ID、名前、状態（有効 / 無効）、証明書の有効期限（期限切れと 30 日以内を目立たせる）、Network Name、登録日時。
- 登録は管理者だけ。入力: 名前（64 バイトまで）、Network Name（255 バイトまで、空なら WLAN）、クライアント証明書（PEM の貼り付けかファイルの選択。ファイルを優先）、有効。

### 7.2 詳細（`/av-clients/{id}`）

- 全員が見られる。項目: 状態、Network Name、Subject、有効期間、SHA-256 フィンガープリント、登録日時、証明書（PEM）。
- 管理者だけが使える操作:
  - 設定の変更（名前、Network Name、有効・無効）。無効にすると、そのクライアントからの接続をすぐに拒否する。
  - 証明書の差し替え（クライアントID と加入者の許可の設定はそのまま。古い証明書ではすぐに接続できなくなる）。
  - 削除（確認ダイアログを出す。各加入者の許可クライアントからも外れる）。

## 8. AV用サーバー証明書（`/av-server-certificate`）

- 全員が見られる。項目: 種類（自己署名 / 持ち込み）、Subject、有効期間、SHA-256 フィンガープリント、更新日時、証明書（PEM）。
- 証明書は `/av-server-certificate.pem` からダウンロードできる（AVクライアントに配るため）。
- 管理者だけが使える操作:
  - 持ち込みの証明書と秘密鍵（PEM の貼り付けかファイルの選択）への差し替え。秘密鍵は画面に戻さない。
  - 自己署名の作り直し（確認ダイアログを出す）。
- 差し替え・作り直しは、再起動なしで以後の新しい接続から使われる。

## 9. ログ（`/logs`）

- 全員が使える。aka-only-server のサーバーログのうち直近 200 件を、新しい順に出す。項目: 日時、レベル、メッセージ、属性（key=value）。
- レベルで絞り込める（すべて / INFO 以上 / WARN 以上 / ERROR のみ）。
- 5 秒ごとに続きを取得し、一覧の先頭に足す（htmx のポーリングと out-of-band の差し替え）。
- 自動更新のリクエストではセッションの有効期限を延ばさない（開いたままでも無操作のタイムアウトが効く）。
- aka-only-server が再起動していたら（`bootId` が変わっていたら）、画面を読み込み直す。

## 10. 監査ログ（`/audit`）

- 管理者だけが使える。2 つのタブで切り替える。

| タブ | 内容 | 項目 |
|---|---|---|
| aka-only-server（`?source=server`） | 管理API の操作（加入者、AVクライアント、AV用サーバー証明書、Ki / OPc の表示） | 日時、操作者、管理クライアント、操作、対象、内容 |
| BFF（`?source=bff`） | ログイン、アカウントの作成・削除、パスワードの再設定・変更 | 日時、操作者、操作元、操作、対象、内容 |

- 新しい順に 50 件ずつ出す。「さらに古いものを表示」で続きを一覧の末尾に足す。
